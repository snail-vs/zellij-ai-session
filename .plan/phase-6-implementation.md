# 阶段 6：选中会话预览

实施日期：2026-09-24。

## 完成范围

- 索引器增加 `preview --agent <name> --session-id <native-id>`，返回统一的用户与 Agent 文本消息、会话 ID 和无法预览的原因。未支持预览的工具明确返回“不支持”，原有扫描和恢复路径未改动。
- Codex 只读扫描原生 JSONL，按 `session_meta` 中的原生会话 ID 选取页面，汇集最近 8 条 `response_item` 文本。OpenCode 只读查询原生 SQLite 的 `message` 与 `part`，按 `session_id` 取最近 8 条文本。
- 插件树视图在宽屏时显示树与右侧预览；窄屏时上下排列。项目显示名称、主目录和会话数量；会话显示标题、工具、目录、运行状态与最近消息。不可用、未写入消息、解析失败、工具不支持分别显示提示。
- 预览由独立命令异步读取，同一时刻只发起一个请求。回包只在会话 ID 仍与当前选中项一致时使用，避免快速移动光标后显示另一会话内容。刷新扫描时重新加载预览。

## 验证

- `cargo test --workspace`：22 个索引器测试、4 个核心测试通过，包括新增的 Codex 与 OpenCode 同目录不同会话 ID 隔离测试。
- 用本机 OpenCode 原生数据库对一个实际会话执行 `preview`，返回最近用户与 Agent 文本。
- `cargo check -p zellij-ai-session-plugin --features wasm`：通过。仓库的 vendor Zellij 依赖缺少内置 WASM 资源；检查时临时放置占位资源，检查后已移除。该检查确认插件 Rust 类型正确，不代表内置 Zellij 资源可用于正式构建。

## 限制和后续接口

- 还需在真实 Zellij Alt-S 浮窗验收宽屏、窄屏、连续移动光标和长消息显示。当前对话预览每条消息最多显示 4 行，保留最近 8 条文本；其他非文本块不会显示。
- Codex 每次读取按原生 ID 扫描 JSONL 目录；插件异步等待，不阻塞方向键处理。历史目录很大时首次预览仍可能有加载延迟。
- 阶段 7 可沿用 `tree_items()`、`selected` 与 `ensure_visible()` 的可见树模型；无需更改预览命令协议。

## 2026-09-24 部署后修复

实际浮窗持续显示 `Loading native history…`。修复了两个插件错误：预览命令改在事件处理阶段发起；回包校验分别比较工作台完整会话键和原生会话 ID。修复后重新构建 WASI 插件，`cargo test --workspace` 全部通过。真实浮窗显示仍需部署后复验。

随后确认仍持续加载的直接原因：预览缓存检查和绘制筛选也误用完整工作台键比较原生 ID，因此成功回包无法显示。已改为与选中会话的 `agent_session_id` 比较。预览区现在显示等待的原生 ID、命令失败详情；10 秒未收到 `RunCommandResult` 时显示超时原因。用本机原生历史实测，Codex 与 OpenCode 的索引器命令分别返回 8 条和 1 条消息。

插件还在请求、回包、超时处写出 `[session-preview]` 诊断日志。更新后的 WASI 插件已构建并安装到本机用户目录，当前 Zellij 会话已重新加载。

用户在重新加载后确认：Alt-S 浮窗已显示预览内容，持续加载问题解除。

## 预览读取性能优化

用户反馈 Codex 预览仍有秒级等待，OpenCode 较快。本机测量发现：Codex 历史目录约 180 个 JSONL、427 MB，旧预览逐行解析全部文件；Debug 版约 3.6 秒，已安装的 Release 版约 510 毫秒，而 OpenCode 预览约 6 毫秒。

Codex 预览现先读取各 JSONL 开头的 `session_meta`，只完整解析原生 ID 匹配的文件；分页文件仍按元信息归并，不依赖文件名猜测会话 ID。相同静态会话的输出哈希在优化前后相同；已安装的 Release 版对约 5 MB 的会话约 12 毫秒，对约 79 MB 的会话约 100 毫秒。`cargo test --workspace` 通过，分页预览测试已覆盖文件名与原生 ID 不同的情况。新索引器已安装到当前用户路径；插件无需重新构建，刷新预览即可使用。
